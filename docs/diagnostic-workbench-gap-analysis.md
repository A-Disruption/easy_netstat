# Diagnostic workbench: capability gaps and feasibility

Audit date: 2026-11-08. Current behavior and code references are in [current state](diagnostic-workbench-current-state.md); proposed boundaries are in [architecture](diagnostic-workbench-architecture.md). All implementation estimates below are relative engineering judgments, not benchmarks or commitments. No Windows acceptance tests were performed.

Priority: **P0** necessary foundation; **P1** first useful expansion; **P2** targeted evidence/correlation; **P3** optional. Complexity: S = contained work, M = several interacting changes, L = substantial Windows integration/testing, XL = deliberately defer or reject. Access classifications describe expected rights, not an elevation guarantee: probe each API and surface partial results; hardened ACLs and protected processes can restrict administrators too.

## A. Connection intelligence

| Capability / current support | Reuse and candidate mechanism | Access and cost | Accuracy limits | Complexity / priority |
| --- | --- | --- | --- | --- |
| TCP listeners/connections, local/remote addresses, state: yes | Existing `get_netstat`, IP Helper owner-PID tables | Normally standard-user; low relative to full process refresh, O(sockets) | Non-atomic sample; state is not a record of packets or reachability | S / P0 preserve |
| UDP endpoints: yes; remote peers: no | Existing UDP enumeration; optional network events/trace for traffic | Baseline standard-user; trace usually elevated and potentially high volume | Bind table has no remote peer or TCP-like state | S preserve; L / P3 peer evidence |
| IPv4/IPv6: yes, scope fidelity incomplete | Typed `SocketAddrV4/V6`; narrow IP Helper adapter or dependency improvement to retain IPv6 scope | Baseline queries; low | `netstat2` drops scope IDs; do not guess a link-local interface | M / P0 |
| PID/name: yes; process generation: no | Existing `sysinfo`; creation time via `GetProcessTimes` if finer identity needed | Limited query rights; O(unique PIDs), cache by generation | Collection races, PID reuse, PID 0/System, incomplete creation-time access | M / P1 |
| Full executable path: no display | Reuse `sysinfo::Process::exe`; `QueryFullProcessImageNameW` fallback | `PROCESS_QUERY_LIMITED_INFORMATION` or query rights; cache | Missing/protected/exited process; NT device paths versus DOS paths; path aliases | S–M / P1 |
| Command line and owner: no display | Explicit on-demand `sysinfo` refresh; process token SID / `GetTokenInformation`, account lookup; `Win32_Process` CIM fallback only if needed | Query/token access; command line may need broader process access; moderate | New processes not covered by initial command-line refresh; secrets in arguments; service account differs from process/impersonated thread identity | M / P1 optional fields |
| Windows service mapping: none | SCM PID-to-many-service map, see D; optional owner-module APIs | Read SCM/service rights; low cached, selected queries moderate | Shared PID is association, not proof of which service owns a socket | M / P1 |
| Transitions, history: none | Diff successful typed snapshots; bounded in-memory journal | No extra privileges; O(n) hash joins, memory proportional to configured bounds | Missed short-lived sockets; a sampling gap is not closure; tuple reuse | M / P1 basic, P2 richer |
| Snapshots / before-after: none | Immutable versioned snapshots, typed diff and provenance | App-owned files; memory/disk capped | Comparing different policy times or hosts requires explicit labeling | M / P3; small manual snapshot may ship earlier |
| Saved filters/views: none | Reuse parser/sort model; versioned local settings | No elevation; negligible runtime cost | Current filter semantics need tests; paths/IPs may be sensitive | S–M / P3 |
| Event-driven observation: none | ETW TCP/IP/kernel providers or WFP net-event subscriptions as supplements | Usually elevated/session ACL dependent; potentially high | WFP net events are not a complete process/socket lifecycle feed; ETW can lose events | L / P2 spike; do not replace polling initially |

Source references: `src/main.rs:121,132,265,552,743,770,1067,1084`. Microsoft's [UDP table API](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedudptable) documents endpoint tables, not UDP sessions. The [owner-module API](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getownermodulefromtcpentry) can return a process, service or component name and can return empty protected-process details. It requires owner-module rows, not the current owner-PID rows. Evaluate TCP6/UDP counterparts separately before claiming full coverage.

**Identity handling:** key processes by host boot/session identity, PID and observed creation time, retaining creation-time precision and availability. A missing timestamp is unknown, not zero. Snapshot generation and first-seen instance distinguish ambiguous observations. Revalidate creation time around on-demand metadata enrichment, expire negative caches, retain original evidence for exited processes, and never look up an old event's PID against today's process list as if it proved ownership. Service restart and socket reappearance must remain distinct observations unless identity evidence links them.

## B. Windows Firewall intelligence

No current firewall collection exists. The existing PID/name/table selection work is useful context but cannot evaluate policy. All rows below depend on typed endpoint identity and an explicit traffic scenario: direction, protocol, concrete local/remote address and port, relevant interface/profile, time, and available application/service identity. A listener alone does not supply remote address, remote port or ingress interface.

| Capability | Recommended source / reusable work | Access / impact | Limitations and implementation size | Priority |
| --- | --- | --- | --- | --- |
| Enabled profiles, defaults, inbound exceptions disabled, merge settings | `Get-NetFirewallProfile -PolicyStore ActiveStore`; COM getters as bounded fallback | Cached, moderate PowerShell startup/provider cost; test standard-user and elevated reads | Preserve effective/local distinction and unspecified values; M | P1/Phase 3 |
| Active interface profile | `Get-NetConnectionProfile` indexed by interface; NLM for native alternative | Usually readable; low cached | Multiple profiles can be active; wildcard listener maps to candidate interfaces; M | P1 |
| Effective rules and policy sources | `Get-NetFirewallRule -PolicyStore ActiveStore -TracePolicyStore`, retain stable rule ID, source/source type and enforcement/status metadata | Provider access may be restricted; batch, on-demand; moderate/high for large stores | Local PersistentStore alone is insufficient; provider/OS/MDM coverage must be tested; L | P1 |
| Program/package match | Associated `Get-NetFirewallApplicationFilter` | Bulk fetch plus association, cached | Match full path, not basename; package/AppID conditions may be unsupported; M | P1 |
| Service restriction | Associated `Get-NetFirewallServiceFilter`; WSH stores where exposed | Read policy and SCM; cached | Evaluate independently from executable; multiple services in PID remain ambiguous; M–L | P1 |
| Protocol / local and remote ports | `Get-NetFirewallPortFilter` | Bulk/cached | Ranges, Any, protocol numbers, dynamic RPC tokens require typed handling; M | P1 common subset |
| Local/remote addresses | `Get-NetFirewallAddressFilter` | Bulk/cached | CIDR/ranges/family, dynamic tokens such as LocalSubnet, DNS/dynamic-address conditions need time-specific resolution or Unknown; M–L | P1 common subset |
| Profiles / interfaces / interface types | Rule profiles plus `Get-NetFirewallInterfaceFilter` and `Get-NetFirewallInterfaceTypeFilter` | Batch/cached | Alias changes, tunnels, missing ingress data, multihoming; M | P1 |
| Allow/block interactions | Candidate matcher with explicit evaluation coverage | Pure CPU over preindexed rules; low/moderate | Ordinary explicit block overrides conflicting allow; advanced security bypass/IPsec/WSH/WFP semantics exceed that simple rule; L | P1 conservative |
| Authentication, identity and other conditions | `Get-NetFirewallSecurityFilter`, connection security policy where needed | Cached; selected enrichment | Unknown principal/IPsec/security conditions must prevent unconditional match claims; L | P2 or unsupported explicitly |
| Actual WFP filters | `FwpmFilterEnum0` / `FwpmFilterGetById0` and provider/layer metadata | WFP object read rights; usually elevated diagnostic path; moderate/high | Compiled filter is not necessarily a friendly firewall rule or reversible rule ID mapping; L | P2 |

[Get-NetFirewallRule](https://learn.microsoft.com/en-us/powershell/module/netsecurity/get-netfirewallrule?view=windowsserver2025-ps) documents ActiveStore as combined applied policy and separate associated filter objects. Fetch and associate the filter categories in the same bounded job, not one PowerShell process per rule or table row. Check snapshot consistency; record start/end, failures and a policy content version. Retain incomplete categories as unavailable. [Profile settings](https://learn.microsoft.com/en-us/powershell/module/netsecurity/get-netfirewallprofile?view=windowsserver2025-ps) need their own effective-store query.

[Application filters](https://learn.microsoft.com/en-us/powershell/module/netsecurity/get-netfirewallapplicationfilter?view=windowsserver2025-ps) and [service filters](https://learn.microsoft.com/en-us/powershell/module/netsecurity/get-netfirewallservicefilter?view=windowsserver2025-ps) are separate conditions. **Running as a service does not inherently invalidate an executable rule.** Check program path, any service-specific restriction, service hardening and all other conditions independently. Never infer a mismatch from service hosting alone.

[Ordinary firewall precedence](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules) supports explaining conflicting block candidates, but a general WFP verdict simulator is not justified. [WFP arbitration](https://learn.microsoft.com/en-us/windows/win32/fwp/filter-arbitration) spans layers/sublayers and callout decisions, including vetoes. Third-party providers and stateful behavior can alter results beyond visible Defender rules. A useful deterministic engine can accurately report tested condition matches/mismatches and qualified likely policy outcomes; it cannot promise end-to-end connectivity or exact universal WFP outcomes.

[INetFwPolicy2](https://learn.microsoft.com/en-us/windows/win32/api/netfw/nn-netfw-inetfwpolicy2) offers profile defaults, rule and service-restriction access, but its local enabled property is not sufficient proof of effective GPO state. It is not automatically equivalent to NetSecurity's provenance/condition coverage. Compare schemas and endpoint results before choosing COM as the primary collector.

## C. Evidence of blocked traffic

No support exists today. Reuse connection/process identity, targeted scenario and bounded history infrastructure; do not run continuous expensive tracing by default.

| Method | Evidence provided | Permissions / expected cost | Limits | Complexity / priority |
| --- | --- | --- | --- | --- |
| Security 5157 | Direct evidence WFP blocked a connection attempt | Security-channel read rights; often elevation or delegated channel access; bounded query low/moderate | Audit Filtering Platform Connection failure auditing must be enabled; event can predate current process/policy | M–L / P2 first |
| Security 5152 | Direct evidence WFP dropped a packet | Same access; high system event volume when enabled | Packet event does not by itself prove a whole application transaction failed | M / P2 only as needed |
| 5156 / 5154 / 5158 | Connection/listen/bind permitted at reported point | Success auditing; potentially very high volume | Permit at one point is not delivery, remote acceptance or application success | M / P2 read if already available |
| WFP net-event enum/subscription | Native classify-drop and related evidence, filter/layer metadata when supplied | `FWPM_ACTRL_SUBSCRIBE`/read rights; normally elevated diagnostics; bounded queues | Events depend on engine options, OS/API version and event type; not every flow produces usable evidence | L / P2 spike |
| Filter runtime-ID lookup | Links event to extant filter/provider/layer | `FWPM_ACTRL_READ`; targeted lookup moderate | Filter may be deleted or engine restarted; no universal friendly-rule mapping | M–L / P2 |
| Existing firewall text log | DROP/ALLOW evidence for recorded tuple/time | File ACLs, often elevated; tail bounded bytes | Logging may be disabled/rotated; limited process/rule attribution, timestamp interpretation | M / P2 fallback |
| ETW / WFP diagnostic capture / pktmon | Targeted event/packet-path evidence and timing | Session ACL/elevation, disk/buffer budget; potentially high overhead | Provider versions, packet loss, payload sensitivity; packets seen do not prove a particular rule caused failure | L / P3 |

[5157](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-5157) provides process/application, network fields, direction and filter/layer runtime IDs; parse structured event fields and preserve raw values. Validate inbound/outbound source-to-local mapping with controlled traces rather than relying on translated text. [5152](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-5152) is packet evidence. [Connection auditing](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/audit-filtering-platform-connection) and [packet-drop auditing](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/audit-filtering-platform-packet-drop) document their separate subcategories and high volume. Prefer 5157 over enabling per-packet audit collection.

**Defaults:** Microsoft's [Audit Policy CSP](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-audit#objectaccess-auditfilteringplatformconnection) documents default 0 (Off/None) for both Filtering Platform Connection and Filtering Platform Packet Drop on its listed client editions/builds. Thus do not expect Security 5157/5152 without the respective failure auditing being configured. This CSP default is not a measurement of every server image or enterprise effective policy: GPO, MDM and security baselines can change it. Establish clean-image/effective defaults in the supported OS test matrix; inspect actual settings using [AuditQuerySystemPolicy](https://learn.microsoft.com/en-us/windows/win32/api/ntsecapi/nf-ntsecapi-auditquerysystempolicy) or read-only `auditpol /get` with subcategory GUIDs. If inaccessible, show audit configuration unknown. [Firewall logging](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/configure-logging) requires enabling drop/success options; do not assume an existing populated log.

WFP engine net-event collection is a different mechanism: [FwpmEngineSetOption0](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmenginesetoption0) documents collect-net-events default 1. This does not imply Security auditing or every event class is enabled. Read actual [engine options](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmenginegetoption0) before use. [Net-event subscription](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmneteventsubscribe0) is version-specific and access-controlled; [enumeration](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmneteventenum5) only includes events logged before the enumeration handle was created. Choose compatible versions at runtime.

Read-only Diagnose should consume existing evidence first. An optional future “temporary collection setup” is a separate authorized operation, because audit/engine/logging toggles change machine state. Its design must record exact prior values, use minimal scoped/duration changes, never edit firewall rules, restore only owned values if unchanged by other administrators/GPO, and report restoration failure. Global audit generation is not reduced by merely filtering this application's subscription. See architecture for cancellation, concurrent changes, crash recovery and cleanup boundaries.

## D. Process/service diagnostics

| Capability / support | Mechanism and reuse | Access / impact | Limitations | Size / priority |
| --- | --- | --- | --- | --- |
| Service names and running PID: absent | `EnumServicesStatusExW(SC_ENUM_PROCESS_INFO)` once per service snapshot; join existing process identities | `SC_MANAGER_ENUMERATE_SERVICE`, query-status visibility; low/moderate | Enumeration can omit inaccessible services; stopped service has no live PID | M / P1 |
| Service path/state/start type/account: absent | `QueryServiceStatusEx`, `QueryServiceConfigW`, optional config2; cache stable config by service name/version | `SERVICE_QUERY_STATUS/CONFIG`; selected enrichment low/moderate | Configured binary command string differs from current process path, wrappers/DLL hosts, configured account is not live token | M / P1 |
| Shared-host attribution: absent | Preserve many services for PID; owner-module API as optional extra evidence | Module queries may need elevation; moderate selected cost | PID map cannot prove socket-level service; do not use undocumented service-tag calls as foundation | M association / P1; L attribution / P3 |
| Restart / termination / crash: absent | Bounded process/service diffs; targeted SCM System, Application Error and WER events; optional existing 4688/4689 | Channel ACLs; low for selected provider/time window | Restart can occur between polls; event service names and crash processes need identity/time matching | M–L / P2 |
| Explain stopped/misbound listener: absent | Compare expected service/port/address supplied by user or saved profile with snapshots | Pure comparison low | Missing listener can be caused by sampling/access gaps; unexpected requires an expectation | M / P1 limited findings |

[SCM enumeration](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-enumservicesstatusexw) supplies process-aware service status. [QueryServiceConfigW](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryserviceconfigw) is configuration for service startup, potentially different from a running instance. [Service security](https://learn.microsoft.com/en-us/windows/win32/services/service-security-and-access-rights) governs visibility; missing association is not proof a process hosts no services. Use [EvtQuery](https://learn.microsoft.com/en-us/windows/win32/api/winevt/nf-winevt-evtquery), structured fields, channel/provider/time filters and bounded paging rather than full Event Viewer functionality. Verify SCM event IDs such as 7031/7034/7036 and Application Error/WER schemas per supported OS before coding rule-specific interpretations.

[Adapters API](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getadaptersaddresses), [interface profile query](https://learn.microsoft.com/en-us/powershell/module/netconnection/get-netconnectionprofile), and [route lookup](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getbestroute2) are primary sources for the proposed context. DNS API details, error-counter interpretation, compartment coverage, capture provider schemas and standard-user access on hardened endpoints still require focused documentation review and endpoint tests.

## Feasibility conclusion

The highest-value feasible expansion is selected-connection process/service identity plus effective policy condition explanations. It does not require traffic capture, a kernel driver, always-on ETW, an exact WFP simulator, a database or a plugin framework. Retain unresolved conditions explicitly; absence of a matching allow rule must never become a confirmed-block finding. Full firewall management, AD administration, general Event Viewer, patching and broad endpoint administration remain outside scope.
